# سرور MCP مولیدو

دستیار هوشمند را مستقیم به دادهٔ فروشگاه وصل می‌کند. بعد از راه‌اندازی
می‌شود پرسید:

- «امروز چقدر فروختیم؟»
- «چه چیزی رو به اتمام است؟»
- «شیر خشک را از کدام بنکدار ارزان‌تر خریده‌ایم؟»
- «کدام کالاها تا یک ماه دیگر منقضی می‌شوند؟»

## راه‌اندازی

```bash
cd mcp && npm install
```

سپس در تنظیمات کلاینت MCP (مثلاً `.mcp.json` در ریشهٔ پروژه):

```json
{
  "mcpServers": {
    "molido": {
      "command": "node",
      "args": ["mcp/server.mjs"],
      "env": {
        "MOLIDO_API": "http://localhost:3000",
        "MOLIDO_EMAIL": "admin@molido.ai",
        "MOLIDO_PASSWORD": "رمز-شما"
      }
    }
  }
}
```

## ابزارها

| ابزار | چه می‌دهد |
|---|---|
| `dashboard` | فروش امروز و ماه، تعداد فاکتور، ارزش موجودی |
| `search_products` | جست‌وجوی کالا با نام، کد یا بارکد |
| `low_stock` | کالاهای زیر حد سفارش |
| `expiring_stock` | بچ‌های نزدیک به انقضا |
| `sales_report` | جمع فروش در بازه |
| `profit_report` | سود ناخالص در بازه |
| `top_products` | پرفروش‌ترین کالاها |
| `purchase_suggestions` | پیشنهاد خرید مریم |
| `price_history` | قیمت بنکداران مختلف برای یک کالا |
| `voice_corpus_status` | آمادگی پیکرهٔ صوتی بلوچی |

## سه تصمیم که عمدی‌اند

**۱. همهٔ ابزارها فقط می‌خوانند.**

دستیار هوشمند گاهی اشتباه می‌کند. اشتباه در «گزارش فروش را بده» یک
جملهٔ غلط است؛ اشتباه در «این فاکتور را ثبت کن» پولِ واقعیِ مشتری است و
موجودی انبار را هم خراب می‌کند. تا وقتی راهی برای تأیید انسانیِ هر
نوشتن نباشد، این مسیر باز نمی‌شود.

**۲. احراز هویت از همان ورودِ عادی می‌آید، نه کلید API.**

جدول `ApiKey` در سامانه هست ولی نه تولید کلید دارد نه نگهبان — یعنی
هنوز کار نمی‌کند. ساختن یک لایهٔ احراز هویتِ آزمون‌نشده، دقیقاً برای
دسترسی دستیار هوشمند، بدترین جای ممکن برای شروع است.

نتیجه‌اش هم درست‌تر است: سرور MCP دقیقاً همان دسترسی‌ای دارد که کاربرِ
واردشده دارد. اگر می‌خواهید دسترسی محدودتر باشد، کاربری با نقش
محدودتر بسازید و همان را در `MOLIDO_EMAIL` بگذارید.

**۳. روی stdio کار می‌کند، نه شبکه.**

هیچ پورتی باز نمی‌شود و از بیرون در دسترس نیست — همان چیزی که برای
دسترسی به دادهٔ مالی درست است.

## آزمون

```bash
node mcp/tools.spec.mjs      # ۳۰ آزمون — تعریف ابزارها، بدون شبکه
node mcp/verify-server.mjs   # ۱۰ آزمون — پروتکل، بدون نیاز به سرور مولیدو
```

هر دو در `run-tests.sh` هستند.

`tools.spec.mjs` تاریخ ثابت می‌گیرد و نه `new Date()`؛ بدون آن، آزمونِ
بازهٔ زمانی فردا نتیجهٔ دیگری می‌داد. همان آزمون در سه منطقهٔ زمانی
اجرا شد — و همان بود که یک اشکال واقعی را لو داد: `toISOString()` تاریخ
را به UTC می‌برد، و نیمه‌شبِ تهران می‌شد ۲۰:۳۰ روزِ قبل. «فروش امروز»
یک روز عقب می‌رفت و هیچ خطایی هم نمی‌داد.
